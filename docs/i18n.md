# Translations

English and Russian ship today. The language is detected from `navigator.languages`, falls back to
English, and the choice is remembered in `localStorage`.

## Adding a locale

A locale is a plain object of string keys — no framework, no build step, no extraction tooling.

1. copy `src/i18n/locales/en.ts` to `src/i18n/locales/<code>.ts` and translate the values;
2. add two lines to `src/i18n/index.ts`: an entry in `LOCALES` and one in `CATALOGUES`.

That is the whole procedure.

**A partial translation is fine.** Anything missing falls back to English, so a locale is useful
from the first string and does not have to be finished before it is merged.

## How lookup works

Locale → English → the key itself.

Returning the key verbatim for an unknown one is what allows *every* user-visible string to go
through `t()`, including labels such as `JPEG` that need no translation at all. It also means a
mistyped key shows up as a visible key rather than a blank label.

`en.ts` is the source of truth and its type defines the key set, so a mistyped key in another locale
is a type error rather than a surprise at runtime.

Placeholders are `{name}` and are substituted from the second argument:

```ts
t('empty.formats', { list: 'PNG, JPEG' })
```

A placeholder with no value is left alone rather than replaced with `undefined`.

## What a switch has to update

Switching the language rebuilds the interface in place. If you add a new piece of chrome, make sure
it is rebuilt too — the toolbar, the generated parameter controls, the empty state, `<html lang>`,
the page title and the meta description all follow the current locale.

Notices store a **key and its values**, not a rendered string, so that they also follow a switch
rather than staying frozen in whatever language they were raised in. Do the same for anything else
that outlives a single render.

## What the tests check

`tests/i18n.test.ts` guards:

- no locale defines a key English does not — a stray key is always a typo, since it can never be
  reached;
- the shipped Russian catalogue is complete, because a gap would silently show English inside a
  Russian interface;
- no message is empty;
- placeholder interpolation, including the "no value given" case.

`e2e/interaction.spec.ts` checks that switching actually rewrites the interface and that the choice
survives a reload.

## Known limitation

Codec errors raised **inside a worker** are resolved with the worker's own detected locale rather
than the chosen one, because workers have no `localStorage`. These are technical strings only. If
this ever matters, the fix is to pass the locale into the worker with the task rather than letting
it detect its own.
